# Фаза 0 — ядро распознавания

**Дата:** 2026-09-01
**Статус:** согласовано, готово к планированию

---

## 1. Задача фазы

Проверить, годится ли выбранная связка моделей для русской речи с техническими терминами, до того как написана хоть одна строка интерфейса. Если качество не устроит, менять модель на этом этапе дёшево.

Фаза заканчивается не работающим приложением, а ответом на вопрос о качестве и парой цифр, на которые можно опереться в фазах 1 и 2.

**Входит в фазу**

- Протокол `Transcriber` и две его реализации: ElevenLabs Scribe v2 и локальный WhisperKit
- Запись микрофона в файл
- Программа командной строки для прогонов и сверки
- Сверка результата с существующей расшифровкой

**Не входит**

- Любой интерфейс, включая менюбар
- Хоткей, вставка текста, постобработка через LLM — это фаза 1
- Запись системного звука, диаризация, очередь — это фаза 2

## 2. Форма проекта

Swift Package без Xcode-проекта. Прогоны запускаются из терминала, тесты — `swift test`.

Причина: в фазе 0 нет ни одной задачи, которой нужен собранный бандл приложения. Даже в Xcode-проекте для прогона файлов пришлось бы завести отдельный консольный таргет, то есть прийти к тому же самому, но более громоздким путём.

Разрешение на микрофон при запуске из терминала macOS выдаёт терминалу, а не программе. Для фазы 0 этого достаточно; приложение запросит своё разрешение в фазе 1. Xcode-проект появится тогда же и подключит этот пакет как локальную зависимость — код останется на месте, переписывать его не придётся.

### Структура

```
Package.swift
Core/
  Transcription/   Transcriber, ScribeTranscriber, WhisperTranscriber, TranscriptionError
  Audio/           MicrophoneRecorder
  Secrets/         Keychain
CLI/               исполняемая программа для прогонов
Tests/
docs/
```

Раскладка повторяет структуру из `CLAUDE.md`. SPM по умолчанию требует складывать исходники в `Sources/`, это переопределяется параметром `path` в `Package.swift`.

Зависимости: только WhisperKit. HTTP делается на `URLSession` из Foundation, разбор аргументов командной строки — вручную. Ни то, ни другое не оправдывает новой зависимости с её обновлениями и лицензией.

## 3. Контракт

```swift
public protocol Transcriber {
    func transcribe(audio url: URL) async throws -> String
}
```

**Вход — файл, а не буфер.** У нас на входе файлы; WhisperKit принимает путь и сам разбирает mp3, m4a и wav; Scribe требует загрузки файла в multipart-запросе. В фазе 1 буфер с микрофона будет сохраняться во временный файл — для нескольких секунд речи это ничего не стоит, а в API его всё равно пришлось бы упаковывать.

**Выход — текст, без таймкодов.** Фазам 0 и 1 таймкоды не нужны ни разу. Фазе 2 они понадобятся для сопоставления с диаризацией, и тогда протокол будет расширен. Закладывать их сейчас значит угадывать, в каком виде они окажутся удобны — по словам или по фразам, — не имея перед глазами кода, который будет их потреблять.

**Настройки не входят в протокол.** Язык, словарь терминов, выбор модели — свойства конкретной реализации, задаются при её создании: `ScribeTranscriber(apiKey:language:keyterms:)`, `WhisperTranscriber.load(model:)`. Иначе в общий интерфейс полезли бы параметры, которых у второй реализации нет.

### Ошибки

```swift
public enum TranscriptionError: Error {
    case fileNotReadable(URL)
    case audioTooShort(TimeInterval)
    case apiKeyMissing
    case requestFailed(status: Int, message: String)
    case modelUnavailable(String)
    case emptyResult
}
```

`emptyResult` стоит отдельно и по существу. Обе модели умеют вернуть пустую строку на тишине или шуме. Если пропустить это дальше как обычный результат, в фазе 1 приложение молча вставит пустоту в текстовое поле, и причину придётся искать вслепую. Пустой результат — ошибка, о которой нужно сказать вслух.

## 4. Реализации

### ScribeTranscriber

`POST https://api.elevenlabs.io/v1/speech-to-text`, ключ в заголовке `xi-api-key`, тело — multipart:

| Поле | Значение |
|---|---|
| `file` | аудиофайл |
| `model_id` | `scribe_v2` |
| `language_code` | `rus` либо не передаётся, см. открытый вопрос |
| `keyterms` | словарь терминов, до 1000 штук по 50 символов |

Из ответа берётся поле `text`. Остальные поля ответа (`words`, `language_probability`, `entities`) в этой фазе не используются.

Ключ читается из Keychain, только на чтение. Записи из кода нет: ключ кладётся один раз командой в терминале.

### WhisperTranscriber

Модель `large-v3-turbo` из репозитория `argmaxinc/whisperkit-coreml`, скачивается при первом запуске, около 1,5 ГБ. Каталог `Models/` уже в `.gitignore`.

Загрузка модели в память вынесена в явный асинхронный конструктор `WhisperTranscriber.load(model:)` и делается один раз перед прогоном. Если спрятать её внутрь первого вызова `transcribe`, первый файл окажется медленным безотносительно своей длины, и замеры времени будут врать.

### Многопоточность

Обе реализации — акторы. Строгая проверка изоляции в Swift 6.2 иначе не пропустит сборку.

## 5. Программа для прогонов

```
nohands transcribe <файл> --engine whisper|scribe
nohands compare <наша-расшифровка> <эталон.txt>
nohands record <секунд> <выход.wav>
```

### Сверка

Материал: запись Телемоста от 2026-03-23, 71 минута, mp3 48 кГц, и расшифровка того же созвона, сделанная сторонним сервисом. Лежат в `~/Documents/Not evil not genius lab/NoHands-testdata`, вне репозитория.

Формат расшифровки: заголовок, блоки `Имя (голос N):`, внутри строки `[ЧЧ:ММ:СС] текст`.

Порядок сверки:

1. Из эталона выбрасываются заголовок, метки спикеров и таймкоды — остаётся сплошной текст
2. Оба текста нормализуются: нижний регистр, без пунктуации, «ё» приводится к «е», пробелы схлопываются
3. Пословное сравнение через расстояние Левенштейна — даёт и процент расхождений, и выравнивание, показывающее вставки, пропуски и замены
4. Выводится процент и список расхождений с контекстом

**Эталон не является истиной.** Это машинная расшифровка стороннего сервиса, то есть конкурент, а не образец. Вопрос фазы стоит не «каков наш процент ошибок», а «лучше или хуже того, чем пользуются сейчас». Поэтому читать нужно список расхождений, а не итоговое число: в каждом расхождении решается, кто из двоих прав.

Результаты прогонов складываются в `NoHands-testdata`, не в репозиторий.

### Запись микрофона

`MicrophoneRecorder` пишет через AVAudioEngine в WAV 16 кГц моно — формат, который обе модели принимают без перекодирования.

Запись нужна, несмотря на наличие готовых файлов: Телемост даёт сжатый звук конференции, а диктовка живёт в противоположных условиях — близкий микрофон, чистый звук, короткие фразы, высокая плотность терминов. Проверять одно по другому нельзя.

Перед записью печатается фактический формат входа: имя устройства, частота дискретизации, число каналов. Это снимает спор о том, узкополосный вход или нет, — видно сразу, до записи.

Планируемый вход фазы 0 — iPhone через Continuity, подключённый кабелем. Это не Bluetooth-профиль гарнитуры: звук идёт широкополосным, 48 кГц. Режим микрофона должен стоять стандартный, а не «Изоляция голоса»: изоляция давит фон агрессивно и прихватывает края слов, и тогда фаза 0 измерит качество шумоподавления Apple вместо качества распознавания.

Проверка нужна ещё и потому, что на машине сейчас нет физического входа вовсе: встроенного микрофона у Mac mini нет, внешний не подключён, а единственное устройство с входными каналами — виртуальный `ZoomAudioDevice`, оставшийся от установки Zoom. Без этой проверки запись пойдёт в него и даст тишину.

## 6. Тесты

Проверяется автоматически всё, что не требует сети и модели:

- парсер эталона: снятие заголовка, меток спикеров, таймкодов
- нормализация текста
- подсчёт расхождений на коротких искусственных примерах
- сборка multipart-тела: границы, заголовки частей
- разбор сохранённого образца JSON-ответа Scribe
- поведение при ошибках: отсутствующий файл, пустой результат

Реальные обращения к API и WhisperKit не мокаются. Подделка сети ради зелёной галочки не проверяет ничего из того, ради чего затевалась фаза; эти прогоны делаются руками.

## 7. Порядок работ

1. Каркас пакета, протокол, ошибки, тесты
2. Сверка: парсер эталона, нормализация, подсчёт расхождений — всё тестируется без сети
3. `WhisperTranscriber`, прогон на 71-минутной записи
4. `ScribeTranscriber`, тот же прогон
5. `MicrophoneRecorder`, диктовка десятка фраз с терминами

Whisper идёт раньше Scribe намеренно: он не требует ключа, поэтому работа не простаивает, пока ключ заводится.

## 9. Открытые вопросы, решаемые прогоном

**Указывать ли язык явно.** `DESIGN.md` говорит не указывать: автоопределение надёжнее при английских терминах в русской речи. Документация ElevenLabs говорит обратное: явное указание улучшает результат. Обе позиции разумны. Решается двумя запросами на одном файле.

**Помогает ли словарь терминов.** У Scribe v2 есть keyterm prompting — до 1000 терминов передаётся прямо в запрос, стоит $0.05 в час сверх базовых $0.22. `DESIGN.md` планирует чинить термины после распознавания, промптом к Haiku. Исправлять уже испорченное слово хуже, чем сразу дать модели знать о его существовании: постобработка не восстановит фамилию или название продукта, которых не знает. Если словарь сработает, часть его переезжает из промпта Haiku в запрос, и `DESIGN.md` требует правки.

## 10. Риски фазы

| Риск | Что делаем |
|---|---|
| Whisper выдумывает текст в паузах длинной записи | Смотрим на расхождения в местах тишины. Если подтвердится — отсечение тишины по уровню, затем Parakeet V3 как запасной вариант |
| Диктовка проверяется через Bluetooth-гарнитуру | Такой вход переключается в узкополосный режим, и вывод о качестве будет ложным. Проверять на проводном входе, USB-микрофоне или iPhone через Continuity |
| Изоляция голоса на входе искажает материал | Режим микрофона ставится стандартный. Иначе измеряется шумоподавление Apple, а не распознавание |
| Расхождений с эталоном много, но непонятно, чьи ошибки | Читается список, а не процент. При сомнении сверяемся с самой записью |
| Загрузка модели 1,5 ГБ при первом запуске | Одноразово, диск позволяет |
