# История диктовок и поведение панели

**Дата:** 2026-09-03
**Статус:** согласовано, готово к планированию

---

## 1. Задача

Фаза 1 закрыта и работает. Несколько дней использования дали пять правок, и все они об одном: приложение должно сообщать владельцу то, что тот обязан знать, и не терять того, что уже сказано.

**Входит**

- История последних десяти диктовок в памяти, доступная из меню одним кликом
- Предупреждение, когда вход работает в узкополосном режиме
- Панель всегда над доком: свёрнутая в покое, развёрнутая на время диктовки
- Получатель текста определяется в момент вставки, а не в начале записи
- Как следствие предыдущего — удаление фиксированного получателя из автомата и механизма активации из вставки

**Не входит**

- Хранение диктовок на диске, поиск по ним, удаление руками
- Окно приложения. Его по-прежнему нет
- Словарь имён и терминов — отложен, см. журнал решений за 2026-09-03
- Всё из фазы 2: системный звук, диаризация, очередь созвонов

## 2. История диктовок

`LastDictation` становится `RecentDictations`: то же место в конвейере, кольцо на десять записей вместо одной.

```swift
@MainActor
public final class RecentDictations {
    public struct Entry: Equatable, Identifiable {
        public let id: UUID
        public let raw: String
        public let cleaned: String?
        public private(set) var audio: URL?
        /// То, что было вставлено: чистый текст, а если чистка не удалась — сырой.
        public var inserted: String { cleaned ?? raw }
        public var wasCleaned: Bool { cleaned != nil }
    }

    public func remember(raw: String, cleaned: String?, audio: URL?)
    /// Новейшая первой.
    public func entries() -> [Entry]
    /// Удаляет удерживаемый аудиофайл. Тексты не трогает.
    public func discardAudio()
}
```

**Актор превращается в главноакторный класс.** Всё, что его касается — координатор и меню, — уже живёт на главном акторе, а меню строится синхронно и ждать не умеет. Асинхронность здесь была ценой без покупки.

**Аудио только у самой свежей.** `remember` действует в таком порядке: удаляет файл у прежней новейшей записи и обнуляет у неё ссылку, затем вставляет новую запись в начало, затем выбрасывает одиннадцатую с хвоста. На диске остаётся ровно один WAV — задел под будущую правку слов сохраняется, речь не размножается.

Порядок важен: если выбрасывать хвост первым, а чистить аудио вторым, то запись, у которой файл ещё не удалён, может уйти из кольца вместе со ссылкой на него, и файл останется на диске навсегда.

**Хранилище переезжает в `AppDelegate`** и передаётся координатору при сборке. Тексты живут, пока живёт приложение; аудио — пока живёт координатор. `DictationCoordinator.stop()` вызывает `discardAudio()` вместо очистки всего: правка из финального ревью фазы 1 сохраняет смысл — файл со speech не переживает teardown, — а «Перечитать конфиг» перестаёт стирать подстраховку.

Эффект автомата `.remember(raw:cleaned:)` не меняется. Аудиофайл подставляет координатор, который им и владеет.

## 3. Подменю «Последние диктовки»

В меню статус-бара, между строкой состояния и «Открыть конфиг».

Строится в момент открытия через `NSMenuDelegate`, поэтому всегда актуально. Новейшая сверху.

Заголовок пункта — результат чистой функции:

```swift
enum MenuTitle {
    /// Схлопывает пробелы и переводы строк в одиночные пробелы, обрезает по границе
    /// и добавляет многоточие. Перевод строки в заголовке пункта меню ломает вёрстку.
    static func short(_ text: String, limit: Int = 60) -> String
}
```

Если чистка не сработала, к заголовку добавляется « · без чистки» — иначе шершавый текст выглядит загадкой.

Клик кладёт в буфер обмена **полный** `inserted`. Пусто — неактивный пункт «пока ничего».

## 4. Получатель — тот, где фокус в момент вставки

Отменяет решение от 2026-09-03 «Вставка мимо цели — это отказ, а не догадка», принятое этим же утром.

Прежняя схема фиксировала получателя в начале записи и отказывалась вставлять, если к моменту вставки фокус ушёл. Реальный сценарий владельца оказался обратным: начать диктовать и переключиться в то окно, куда нужен текст. При такой работе фиксация в начале не защищает, а мешает.

**Следствия — вычитающие.**

- Из `DictationMachine` уходит `TargetApp`: из событий, состояний, эффекта `.insert` и состояний панели. После смены правила он не определяет ничего, а понятие с именем «получатель», ничего не определяющее, хуже отсутствия понятия. Тип `TargetApp` удаляется целиком.
- Из `TextInserter` уходят `bringToFront`, `ActivationPlan` и отказы `targetNotRunning` и `targetDidNotComeForward` вместе с их тестами. Защищать нечего: вставка по определению идёт туда, куда смотрит владелец.
- `TextInserter.insert(_ text: String)` теряет параметр цели.

Остаётся вся механика буфера обмена: снимок, запись, Cmd+V с очищенными флагами, задержка, возврат прежнего содержимого только если `changeCount` не изменился.

**Что панель показывает вместо получателя.** Активное приложение живьём: `App` подписывается на `NSWorkspace.didActivateApplicationNotification`, обновляет модель панели и берёт начальное значение из `frontmostApplication` при запуске. Панель не врёт по построению — она показывает то же, что видит система.

## 5. Панель всегда над доком

Панель перестаёт появляться и исчезать. Она висит всегда, в двух видах:

| Вид | Когда | Что показано |
|---|---|---|
| свёрнутый | в покое | узкая полоска с иконкой микрофона |
| развёрнутый | от начала записи до конца вставки | как сейчас: приложение, уровень, стадия, отказ |

Свёрнутый вид — это знак «приложение живо». Если полоски нет, значит приложение не запущено, и это ровно та информация, ради которой пункт заведён.

Реализация мелкая: `hide(after:)` перестаёт делать `orderOut` и просто сбрасывает состояние модели в nil, а nil в модели теперь означает не «панели нет», а «панель свёрнута». Окно выводится вперёд один раз при создании.

Размер окна не меняется; свёрнутый вид — маленькая плашка внутри прозрачного окна. События мыши панель по-прежнему не принимает, поэтому кликам под ней не мешает.

**Известная цена.** Полоска видна поверх всего, включая полноэкранные приложения, и перекрывает нижнюю кромку содержимого. Принято сознательно; если окажется навязчивым, прятание добавим отдельно.

## 6. Предупреждение об узкой полосе

`DESIGN.md` в таблице рисков обещает: «Приложение проверяет тип активного устройства ввода перед стартом записи и предупреждает, если это Bluetooth». В CLI такая проверка есть с фазы 0, в приложении её нет. Фаза 1 закрылась с невыполненным требованием; поймано на живой диктовке через AirPods Pro — 24 кГц, при пороге 32 кГц.

Порог и предикат переезжают в `Core/Audio` рядом с `AudioInputDevice`:

```swift
extension AudioInputDevice {
    public static let narrowbandThreshold: Double = 32000
    public var isNarrowband: Bool { sampleRate < Self.narrowbandThreshold }
}
```

Координатор при старте записи спрашивает устройство и отдаёт наружу частоту отдельным замыканием, рядом с существующим `onLevel`:

```swift
/// Частота входа, если она ниже порога, и nil, когда полоса нормальная.
/// Вызывается один раз при старте записи.
onNarrowbandInput: @MainActor (Double?) -> Void
```

Формулировку пишет `App`: «узкая полоса, 24 кГц» рядом с именем приложения. У CLI остаётся своя, длинная. Координатор передаёт факт, а не текст: интерфейсные формулировки в модуле `Dictation` не живут.

Мимо автомата — сознательно. Автомат про устройства не знает и знать не должен; проводить это через событие означало бы править автомат, его тесты и состояния панели ради строки текста.

**Только предупреждение.** Запись идёт как обычно, ничего не блокируется, устройство не переключается.

## 7. Отказы

После удаления активации у вставки остаются два отказа, оба уже существуют:

| Что случилось | Что делаем |
|---|---|
| нет разрешения на управление компьютером | текст остаётся в буфере обмена, панель называет причину |
| не удалось синтезировать нажатие | то же самое |

Остальные пути отказа фазы 1 не меняются.

## 8. Что тестируется

| Тестируется | Обёртка, тестов нет |
|---|---|
| кольцо: порядок, вытеснение одиннадцатой, аудио только у свежей, `discardAudio` | подменю `NSMenu` |
| `MenuTitle.short`: короткий текст, длинный, перевод строки, схлопывание пробелов | панель и свёрнутый вид |
| `Entry.inserted` и `wasCleaned` на обеих ветках | подписка на `NSWorkspace` |
| `AudioInputDevice.isNarrowband`: порог с обеих сторон | |
| автомат после удаления `TargetApp` — существующие тесты, приведённые к новой форме | |

Тест раньше кода. Удаление `TargetApp` тестов не добавляет: оно их упрощает, и ни одно утверждение при этом не ослабляется.

## 11. Открытые вопросы

**Навязчивость постоянной панели.** Решится наблюдением: если полоска начнёт мешать, вариантов два — прятать в полноэкранном режиме или прятать по таймеру бездействия. Заранее не выбираем.

**Достаточно ли десяти.** Число выбрано из соображения «сеанс работы целиком, меню читается с одного взгляда». Если окажется мало, оно станет полем конфига; сейчас константа.
