# Синхронизация с Todoist — срез 2: остальные операции Башка → Todoist

**Статус:** согласовано
**Дата:** 2026-10-07
**Дополняет:** `docs/superpowers/specs/2026-10-07-todoist-sync-design.md`. Модель, границы и решения v1 действуют без изменений; здесь — только то, что добавляет второй срез.

---

## 1. Задача

Первый срез научил Башку создавать задачи в Todoist. Всё остальное, что владелец делает с задачей в чате Башки, до Todoist не доходит. Если задачу переформулировать, отметить сделанной или отменить, в Todoist она остаётся прежней и открытой. Новый проект появляется в Todoist только вместе с первой задачей, а завершённый проект продолжает висеть там среди активных.

Кусок считается сделанным, когда любая правка задачи или проекта в Башке доходит до Todoist. А правка, которая не дошла, остаётся видимой в board и отправляется снова сама.

## 2. Что установлено разговором

**Операцию определяет реплика владельца.**

| Реплика | Операция |
|---|---|
| новая задача | создание (срез 1) |
| правка задачи с `todoist:` | изменение |
| «сделал» | закрытие |
| «не будем», «передумал» | удаление |

Признак «у задачи уже есть `todoist:`» отличает изменение от создания. Различие между «сделал» и «передумал» хранит Todoist: в первом случае задача закрывается, во втором удаляется, хотя из board обе уходят одинаково.

**Неподтверждённая операция остаётся в board с пометкой.** Строка закрытой или удалённой задачи уходит из board только после подтверждения Todoist. Пока его нет, она стоит с пометкой. Закрытие и удаление ведут себя одинаково.

**Помеченное отправляется снова при любом контакте.** Повтор происходит при сообщении владельца в чат, при ingest или по прямой просьбе. Отдельной команды «досинхронизируй» нет.

**Проект появляется в Todoist вместе со страницей.** Когда заводится страница проекта, создаётся и проект в Todoist. Когда проект переходит в `paused` или `done`, он архивируется.

## 3. Что предложено и принято вместе с дизайном

- **Изменение отправляет всю текущую задачу:** название, описание, срок, проект, а не только изменённые поля. Повтор безопасен, и агенту не нужно помнить, что именно поменялось.
- **Смена проекта — тоже изменение.** Задача переносится в другой подпроект.
- **Изменение, закрытие и удаление повторяемы.** Они адресованы `id`, поэтому повтор не создаёт дублей. Ответ «задачи уже нет в Todoist» на закрытие или удаление считается успехом.
- **Пометки в строке задачи:**
  - `· todoist-pending:update`, `:close`, `:delete` — операция ещё не подтверждена;
  - `· todoist-pending:create` — создание точно не дошло: NoHands не ответил или ответил `503`;
  - `· todoist-check` — исход создания неизвестен (`504`, `502`, обрыв). Автоповтора нет, вопрос владельцу.

  Последние две пометки закрывают дыру первого среза: такая задача раньше просто оставалась без `todoist:`.
- **Проект создаётся только для страницы, заведённой как `active`.** Исторические проекты, заведённые ради кейсов, в Todoist не попадают. Переход `paused` → `active` разархивирует проект.
- **Сбой операции с проектом** отмечается во frontmatter страницы полем `todoist_pending: create | archive | unarchive` и повторяется по тем же правилам.
- **Не входит:** переименование проекта или области.

## 4. Канал Башка → NoHands

Тот же локальный HTTP на `127.0.0.1:41730`. Новые запросы:

| Запрос | Тело | Что делает NoHands |
|---|---|---|
| `PUT /tasks/<id>` | как у `POST /tasks`: `title`, `description`, `due`, `area`, `project` | находит или создаёт область и проект; обновляет название, описание, срок; переносит задачу, если её проект в Todoist не совпадает с целевым |
| `POST /tasks/<id>/close` | — | закрывает задачу |
| `DELETE /tasks/<id>` | — | удаляет задачу |
| `POST /projects` | `area`, `project` | находит или создаёт область и подпроект; отвечает `id` проекта |
| `POST /projects/archive` | `area`, `project` | архивирует подпроект |
| `POST /projects/unarchive` | `area`, `project` | разархивирует подпроект |

`description` и `due`, отсутствующие в `PUT`, значат «пусто»: описание очищается, срок снимается. Это следует из правила «отправляется вся задача».

### Ответы

- Успех — `200`, а для `POST /projects` — `201`, если проект создан, и `200`, если найден.
- Задачи нет в Todoist (`404` от Todoist) при закрытии и удалении — `200` с `"already": true`.
- При изменении то же значит, что задача удалена в Todoist, — `404`. Агент сообщает владельцу и строку не меняет.
- Остальные коды — как в срезе 1: `400`, `409`, `502`, `503`.
- Для повторяемых операций `504` не нужен: исход «неизвестен» безопасно повторить.

### Журнал

Каждое действие записывается в тот же журнал, что и в срезе 1. Новые виды: `task.updated`, `task.moved`, `task.closed`, `task.deleted`, `project.archived`, `project.unarchived`. Их будет читать третий срез, чтобы отсеивать эхо.

### Todoist API v1

- изменение — `POST /api/v1/tasks/<id>`;
- перенос — `POST /api/v1/tasks/<id>/move` с `project_id`;
- закрытие — `POST /api/v1/tasks/<id>/close`;
- удаление — `DELETE /api/v1/tasks/<id>`;
- текущий проект задачи — `GET /api/v1/tasks/<id>`;
- архив — `POST /api/v1/projects/<id>/archive` и `/unarchive`.

Как снимать срок, план проверяет живым запросом до написания кода: `due_date: null` или `due_string: "no date"`. `due_string` допустим только для снятия срока, а не для установки: при установке он разбирается по языку.

## 5. Изменения в Башке

- **Схема (`AGENTS.md`, раздел «Todoist»):**
  - реплика → операция;
  - запросы на изменение, закрытие, удаление;
  - пометки и их повтор при любом контакте;
  - строка закрытой или удалённой задачи уходит только после подтверждения;
  - запись `task` в log — после подтверждения.
- **Проекты:** при заведении страницы со `state: active` — `POST /projects`. При смене `state` — архив или разархивация. Сбой — `todoist_pending:` во frontmatter.
- **Первый срез:** правила повтора создания заменяются пометками `todoist-pending:create` и `todoist-check`.

## 6. Проверка

1. Тесты NoHands на каждый новый запрос:
   - успех;
   - «задачи уже нет»;
   - перенос между проектами;
   - снятие срока;
   - журнал;
   - отказ Todoist.
2. На живом Todoist — тестовая задача, созданная через `POST /tasks`:
   - переименовать;
   - перенести в другой подпроект;
   - снять срок;
   - закрыть;
   - повторить закрытие — `"already": true`.

   Вторая тестовая задача — удалить. Тестовый проект: создать, архивировать, разархивировать, затем удалить руками.
3. В Башке: выключенный NoHands → «сделал» по задаче → строка остаётся с `todoist-pending:close` → NoHands включён → следующее сообщение в чат → строка ушла, запись в log.
