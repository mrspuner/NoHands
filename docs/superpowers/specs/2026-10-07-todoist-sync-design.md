# Синхронизация задач Башки и Todoist

**Статус:** согласовано
**Дата:** 2026-10-07
**Относится к:** новой подсистеме NoHands; меняет границу, проведённую записью журнала от 2026-09-07 «Захват выделения живёт в NoHands, разбор — снаружи»

---

## 1. Задача

Задачи владельца живут в двух местах. Башка — личная база знаний о работе по паттерну LLM Wiki: markdown-файлы, которые ведёт агент, задачи лежат в `wiki/board.md` под своими проектами. Todoist — место, куда владелец смотрит утром и где отмечает сделанное.

Сейчас между ними нет связи. Задача, поставленная в разговоре с Башкой, в Todoist не попадает, а галочка в Todoist Башке не видна.

Нужна двусторонняя синхронизация: задачи, заведённые, изменённые, закрытые или удалённые в одном месте, без ручной работы оказываются в том же состоянии во втором.

Кусок считается сделанным, когда задача, поставленная в чате Башки, сама появляется в Todoist в нужном проекте, а её идентификатор возвращается в строку `board.md`.

## 2. Что установлено разговором

**В Башке нет программной части.** Это схема, markdown и агент. Всё, что требует постоянно работающего процесса, живёт в NoHands.

**NoHands — единственные ворота в Todoist.** Всё, что Башка меняет в Todoist, проходит через одну точку. Поэтому NoHands знает, что сделал сам, и может отличить собственное действие от действия владельца.

**Синхронизация событийная, без снимков.** Сравнение двух полных снимков требует правил на каждый случай отсутствия: задача новая, удалённая или закрытая и убранная выглядят одинаково. Sync API Todoist сам отдаёт изменения с прошлого запроса, включая признаки удаления и выполнения, поэтому сравнивать нечего.

**Обратный путь — опрос, а не webhook.** Webhook требует адреса, доступного из интернета по HTTPS, а Mac mini стоит за роутером. Опрос раз в минуту обходится без сервера; цена — задержка до минуты.

**Идентификатор выдаёт только Todoist.** Своих идентификаторов Башка не заводит: два источника идентификаторов потребовали бы таблицы соответствия.

**Создание задачи в Todoist — это «ок» владельца.** Правило Башки «задачу в board пишешь только после "ок"» распространяется на Todoist: задачу там заводит сам владелец.

**Лишних файлов в Башке нет.** Эхо собственных изменений гасится в NoHands, до того как появится файл. Файл в `raw/` Башки пишется только при реальном изменении.

**Последнее изменение побеждает, и побеждает задача целиком.** Если задачу поменяли с обеих сторон между двумя опросами, правка поля со стороны, проигравшей по времени, теряется. При опросе раз в минуту случай редкий, и владелец принял его сознательно.

**Удаление — не выполнение.** Задача, удалённая в Todoist, удаляется и в Башке, а в журнале Башки остаётся «удалена», а не «закрыта».

## 3. Модель

```
чат → ingest Башки → curl localhost → NoHands → Todoist → id → ответ → id в board.md
Todoist → опрос раз в минуту → NoHands (своё? → отбросить) → raw Башки → ingest (claude -p) → board + log
```

### Что синхронизируется

Задачи: создание, изменение, закрытие, удаление, в обе стороны. Поля: название, описание, срок, проект.

Проекты:

- проект, заведённый в Башке, автоматически заводится в Todoist;
- о проекте, заведённом в Todoist, Башка спрашивает владельца;
- проект, от которого владелец отказался, запоминается NoHands, и вопрос больше не повторяется.

Личные проекты Todoist в Башку не попадают. Граница проходит по наличию пары: синхронизируется только то, у чего есть проект-пара в Башке.

### Соответствие проектов

Вложенность сохраняется. Область Башки — родительский проект Todoist, проект Башки — его подпроект.

Имена различаются: в Башке проект называется слагом (`khibiny`), в Todoist — по-человечески («Хибины»). Пара названий хранится в Башке: у проекта во frontmatter его страницы (`todoist: "Хибины"`), у области — в схеме, рядом со списком областей.

Задачи из секции «Общее» области идут в родительский проект. Бэклог Башки не синхронизируется: это идеи, а не задачи.

### Где что хранится

| Что | Где |
|---|---|
| Идентификатор задачи | строка задачи в `board.md`: `· todoist:<id>` |
| Пара названий | Башка: frontmatter проекта, схема для областей |
| Журнал собственных действий | NoHands, вне репозитория |
| Токен синхронизации Sync API | NoHands, вне репозитория |
| Отклонённые проекты | NoHands, вне репозитория |
| Токен Todoist | Keychain, сервис `nohands-todoist`, тот же, что у скилла `inbox-review` |

## 4. Границы куска

**Входит — первый срез, исходящий путь:**

- локальный HTTP-сервер в NoHands
- создание задачи из чата Башки
- автосоздание в Todoist недостающей области и проекта
- журнал собственных действий, уже с первого среза
- правки схемы Башки, последним шагом

**Не входит и делается следующими срезами:**

- **Обратный путь**: опрос, фильтр эха, запуск ingest
- **Изменение, закрытие и удаление** в обе стороны
- **Проекты из Todoist** с вопросом владельцу и списком отклонённых

Журнал входит в первый срез, хотя читать его будет только второй: без него второй срез начался бы с переделки первого.

## 5. Канал Башка → NoHands

**Локальный HTTP на `127.0.0.1`, фиксированный порт.** Выбран потому, что его можно проверить руками обычным `curl`. Снаружи машины адрес не виден.

Токена доступа нет. Он защитил бы от других программ на этой же машине, а для машины одного владельца это лишнее.

Отвергнуто:

- **Unix-сокет.** То же самое, но с ограничением доступа правами файла и с менее удобной ручной проверкой.
- **XPC.** Родной механизм macOS, но требует больше настройки и почти не поддаётся ручной проверке.

**Отдельного CLI нет.** Агент Башки зовёт `curl` сам. Это повторяет устройство `inbox-review`, где Todoist вызывается из сессии без нового бинарника.

Логика повторов описана в схеме Башки, а не в коде:

1. Три попытки запроса.
2. Если не получилось — `open -a NoHands` и ещё одна попытка.
3. Если и это не помогло — сказать владельцу в чате, что задача в Todoist не ушла.

Отвергнут CLI-бинарник: логика повторов и запуска жила бы в коде, но ценой ещё одной программы.

Плюс того, что запрос идёт через приложение, а не мимо него: исходящие действия и будущий опрос живут в одном процессе, и память о собственных действиях лежит в одном месте.

## 6. Создание задачи

### Запрос

```
POST http://127.0.0.1:<порт>/tasks
Content-Type: application/json

{
  "title": "Собрать список внедрённых правок",
  "description": "Строка-описание из board.md, может отсутствовать",
  "due": "2026-10-10",
  "area": "Сколково",
  "project": "Хибины"
}
```

- `area` и `project` — имена из пары в Todoist, а не слаги Башки.
- `project` отсутствует для задачи из «Общего».
- `due` — только дата, `ГГГГ-ММ-ДД`, и только если срок назван.

### Что делает NoHands

1. Находит среди проектов Todoist родительский проект с именем `area`. Если его нет — создаёт.
2. Если задан `project`, находит подпроект с этим именем внутри найденного родителя. Если его нет — создаёт с `parent_id` родителя. Ищется пара «родитель + имя», а не имя по всему аккаунту: одинаковые имена в разных областях не должны склеиться.
3. Создаёт задачу: `POST /api/v1/tasks` с `content`, `description`, `due_date`, `project_id`.
4. Записывает в журнал каждое своё действие: созданный проект и созданную задачу.
5. Отвечает агенту.

Срок передаётся полем `due_date`, а не `due_string`. Урок `inbox-review`: строка разбирается по языку и на русской фразе молча даёт не тот день. Эндпоинт — `/api/v1/`, старый `/rest/v2/` отвечает `410`.

### Ответ

Успех — `201`:

```json
{ "id": "6hRvqqQ89g3prC7Q", "project_id": "…", "created_projects": ["Хибины"] }
```

`id` — непрозрачная строка, а не число. Агент берёт его из ответа и только из ответа.

**Ответ без `id` значит, что задача не создана.** Тогда `todoist:` в `board.md` не пишется вовсе, а отказ называется вслух. Придуманный идентификатор подтвердил бы задачу, которой нет. Это то же правило, что для `card.md` в `inbox-review`.

Отказ — код ошибки и текст причины:

- `400` — запрос неполный;
- `502` — Todoist ответил ошибкой, его код и текст передаются дальше;
- `503` — нет токена в Keychain.

Тихих фолбэков нет. Это правило проекта: внятная ошибка вместо тихой подмены.

### Журнал собственных действий

Файл вне репозитория, строка JSON на действие: время, вид действия, идентификатор в Todoist. Пишется до ответа агенту.

Во втором срезе опрос сверяет каждое пришедшее событие с журналом. Совпавшее — эхо собственного действия, оно отбрасывается и в Башку не попадает.

## 7. Изменения в Башке

Делаются последним шагом среза, когда эндпоинт уже отвечает. Иначе ingest начнёт стучаться в адрес, которого нет.

- **Схема (`AGENTS.md`):**
  - после записи задачи в board — запрос в NoHands по разделу 5;
  - формат `· todoist:<id>` в строке задачи;
  - пара названий для областей;
  - создание задачи в Todoist как «ок» владельца;
  - Бэклог не синхронизируется.
- **Страницы проектов:** поле `todoist:` во frontmatter.

## 8. Проверка

Первый срез проверяется на живом Todoist:

1. `curl` руками на эндпоинт: задача в существующем проекте, задача с новой областью и проектом, задача из «Общего», запрос без токена в Keychain.
2. Сценарий целиком: задача, поставленная в чате Башки, появляется в Todoist в нужном подпроекте. `id` из ответа стоит в строке `board.md` и совпадает с идентификатором в Todoist.
3. Повторный запрос с той же областью не создаёт второго родительского проекта.
