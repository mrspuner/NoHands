# Синхронизация с Todoist — срезы 3–5: обратный путь Todoist → Башка

**Статус:** согласовано (владелец поручил делать без его участия, решения записаны как решения исполнителя)
**Дата:** 2026-10-07
**Дополняет:** `2026-10-07-todoist-sync-design.md` (модель v1) и `2026-10-07-todoist-sync-slice2-design.md`

---

## 1. Задача

Срезы 1–2 провели весь путь Башка → Todoist. Обратного пути нет: задачу закрыли, поправили или завели в Todoist, а Башка об этом не знает.

Кусок считается сделанным в трёх шагах, по одному на срез:

- **Срез 3.** Задача закрыта или удалена в Todoist — через минуту её строки нет в board, а в log есть запись.
- **Срез 4.** Задача заведена или изменена в Todoist в рабочем проекте — через минуту она в board в нужном виде.
- **Срез 5.** В Todoist появился новый проект в рабочей области — при следующем сообщении в чат агент спрашивает, добавить ли его. На «нет» NoHands больше не спрашивает и не присылает его задачи.

## 2. Что установлено раньше (v1)

- Синхронизация событийная. Изменения отдаёт Sync API с прошлого токена.
- Опрос раз в минуту, без сервера.
- Эхо собственных действий гасится в NoHands, до появления файла.
- Файл в `raw/` пишется только при реальных изменениях.
- Ingest запускается автоматически.
- При конфликте побеждает последняя версия задачи целиком.
- Удаление — не выполнение.
- Создание задачи в Todoist самим владельцем равно его «ок».
- О проекте из Todoist Башка спрашивает. Отклонённый проект NoHands запоминает.
- Личные проекты Todoist в Башку не попадают.

## 3. Решения исполнителя (владелец не участвовал)

### 3.1. Что такое «рабочее»

**Рабочее — всё, что лежит внутри областей Башки.** NoHands получает список имён областей из своего `config.json`, раздел `todoist`:

```json
"todoist": {
  "bigheadPath": "/Users/macintosh/BigHead",
  "areas": ["Сколково", "RooX", "Обновление портфолио и поиск работы"],
  "claudePath": "/Users/macintosh/.local/bin/claude",
  "pollSeconds": 60
}
```

- Задача рабочая, если корневой предок её проекта — область из списка.
- Если список пуст или `bigheadPath` не задан, опрос не запускается. В строке статуса меню появляется причина.
- Новая область в Башке — новая строка в списке. Это правило в схеме.

**Почему не читать области из `AGENTS.md`.** Разбор чужого markdown-файла ломается при первой правке таблицы. Файл настроек NoHands уже существует и правится руками, так что ещё одна строка в нём — дешёвая цена.

### 3.2. Опрос

- `POST /api/v1/sync` с `{"sync_token": …, "resource_types": ["items", "projects"]}`. Интервал — `pollSeconds`, по умолчанию 60.
- **Первый запуск — без событий.** Полная синхронизация (`"*"`) только запоминает токен и карту проектов (id → имя, родитель). Иначе все существующие задачи пришли бы в Башку как новые.
- **Состояние** лежит в `~/Library/Application Support/NoHands/todoist-sync-state.json`, вне репозитория: токен, карта проектов, список отклонённых проектов. Записывается после каждого успешного опроса.
- **Сбой опроса** (сеть, Todoist, Keychain) не роняет приложение. Он пишет причину в строку статуса и повторяется на следующем такте. Токен не сдвигается, поэтому изменения не теряются.
- Опросы не накладываются друг на друга. Пока идёт один опрос и его ingest, следующий такт пропускается.

### 3.3. События

По каждой изменённой задаче из рабочей области, не из отклонённого проекта:

| Признак в Sync | Событие |
|---|---|
| `is_deleted: true` | `deleted` |
| `checked: true` | `closed` |
| иначе | `changed` — название, описание, срок, проект, область, `added_at` |

`changed` не различает «создана» и «изменена». Это различает Башка: если `id` есть в board — изменение, если нет — новая задача. Так решил сам владелец в начале проектирования («башка проверит id»).

По каждому новому проекту, родитель которого — область, приходит событие `project_added`.

### 3.4. Фильтр эха

Событие отбрасывается, если в журнале собственных действий есть запись с тем же `id` и временем не раньше, чем `updated_at` события минус 5 секунд.

**Почему по времени, а не по виду действия.** Журнал пишется после ответа Todoist, то есть после изменения у Todoist. Своя запись поэтому всегда позже его `updated_at`. Правка владельца, сделанная позже нашей, имеет `updated_at` позже нашей записи и проходит. Повторные строки журнала, например двойное закрытие, фильтру не мешают.

**Чем платим.** Правка владельца в Todoist в течение 5 секунд после нашей будет принята за эхо. Это маловероятно.

### 3.5. Файл в Башке

- **Задачи.** Одно событие или пачка за опрос — один файл `raw/YYYY-MM-DD-todoist-HHMMSS.md`, вид `todoist`.
- **Проекты.** Новые проекты — отдельный файл `raw/YYYY-MM-DD-todoist-project-HHMMSS.md`, вид `todoist-project`.
- Файл пишется только при наличии событий.

Формат файла задач:

```markdown
---
kind: todoist
polled_at: 2026-10-07T15:04:00Z
---

- event: closed
  id: 6hhVXx8M3P59PM53
  title: Внести правки к прогону 08.10
  area: Сколково
  project: Переход Хибин на модель одного админа
  updated_at: 2026-10-07T15:03:41Z

- event: changed
  id: 6hhVabc…
  title: Новая задача из Todoist
  description: …
  due: 2026-10-12
  area: RooX
  project: ИНДИД
  added_at: 2026-10-07T15:03:50Z
  updated_at: 2026-10-07T15:03:50Z
```

- Поля без значения не пишутся.
- Задача прямо в области, не в подпроекте, — без `project`.
- Текст задач подставляется как есть, без экранирования markdown. Это источник, и `raw/` не правится.

### 3.6. Автоматический ingest

После записи файла задач NoHands запускает агента Башки:

```
claude -p "<промпт>" --permission-mode acceptEdits --allowedTools Read Edit Write Glob Grep
```

Запуск идёт в папке `bigheadPath`. Промпт: обработать `raw/<файл>` по разделу «Todoist → входящие» схемы, вопросов не задавать.

- **Без `Bash`.** Агент физически не может обратиться к NoHands. Значит, применение события из Todoist не уходит обратно в Todoist: эха со стороны Башки нет.
- **Таймаут — 10 минут.** Запуски идут строго по одному.
- **Сбой** (нет `claude`, ненулевой код, таймаут) пишет причину в строку статуса. Файл остаётся необработанным, и его подберёт следующий разговор: необработанный raw уже есть в схеме Башки. Ничего не теряется.
- **Файлы проектов агент не обрабатывает.** Они ждут разговора с владельцем.

### 3.7. Отклонённый проект

`POST /projects/ignore` с `{"area", "project"}`:

- NoHands находит проект по паре «область + имя» и запоминает его `id` в состоянии.
- Задачи и подпроекты этого проекта больше не превращаются в события.
- Ответ `200`. Неизвестный проект — `404`.

### 3.8. Правила Башки (схема, раздел «Todoist → входящие»)

Ingest файла вида `todoist`, по событиям:

- **`closed`, `id` есть в board.** Строку убрать. В log: «закрыта в Todoist».
- **`deleted`, `id` есть в board.** Строку убрать. В log: «удалена в Todoist».
- **`closed` или `deleted`, `id` нет в board.** Ничего.
- **`changed`, `id` есть в board.** Строку привести к событию: текст, строка описания, срок, секция проекта по полю `todoist:` страниц.
  - Пометка `todoist-pending:update` снимается: последняя правка — в Todoist.
  - Пометки `:close` и `:delete` остаются: решение владельца в Башке позже по смыслу и уйдёт при следующем контакте.
- **`changed`, `id` нет в board**, а проект — страница с таким `todoist:` или сама область. Новая строка `- [ ] <title> · добавлена <дата added_at> · todoist:<id>`, строка описания под ней, в секции проекта или в «### Общее» области. Секции нет — создать.
- **`changed`, проект не связан ни с одной страницей.** Ничего; в log отметить, что событие пропущено.
- Срок пишется в строку задачи как « — срок ГГГГ-ММ-ДД», как сейчас в board.
- Вопросов в автоматическом ingest нет. Всё, что потребовало бы вопроса, записывается в log как пропущенное.

Файл вида `todoist-project` при следующем разговоре:

- агент спрашивает про каждый проект: «добавить X в Башку?»;
- на «да» — страница проекта со `state: active` и `todoist:` = имя (проект в Todoist уже есть, `POST /projects` ответит `200`);
- на «нет» — `POST /projects/ignore`;
- затем запись `ingest` в log.

## 4. Не входит

- Переименование и удаление проектов в Todoist.
- Подзадачи Todoist (`parent_id` у задач) — идут как обычные задачи.
- Повторяющиеся задачи — закрытие повторяющейся задачи в Todoist сдвигает срок, а не закрывает её. Придёт как `changed` с новым сроком.
- Метки, приоритеты, разделы.

## 5. Проверка

1. Тесты NoHands:
   - разбор ответа Sync;
   - первый запуск без событий;
   - классификация `closed` / `deleted` / `changed`;
   - фильтр области и отклонённых проектов;
   - фильтр эха на границе 5 секунд;
   - формат файла;
   - запуск ingest через подменяемый исполнитель процесса: успех, ненулевой код, таймаут;
   - сохранение и чтение состояния;
   - `POST /projects/ignore`.
2. На живом Todoist, после установки:
   - закрыть в Todoist задачу из board → через минуту строки нет, в log запись;
   - завести задачу в «Сколково» → появилась в «Общее»;
   - поменять ей срок → строка обновилась;
   - удалить её → строки нет;
   - создать подпроект в области → файл `todoist-project`, автоматический ingest его не трогает;
   - закрыть задачу через Башку (срез 2) → эхо отфильтровано, нового файла нет.
