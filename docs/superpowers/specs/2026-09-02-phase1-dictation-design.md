# Фаза 1 — диктовка

**Дата:** 2026-09-02
**Статус:** согласовано, готово к планированию

---

## 1. Задача фазы

Довести диктовку до состояния, в котором подписку VoiceOS можно отменить: зажал клавишу, наговорил, отпустил — текст появился в активном поле любого приложения.

Фаза заканчивается работающим приложением в статус-баре и несколькими днями реального использования, после которых станет виден список правок.

**Входит в фазу**

- Форма приложения: бандл `.app`, собираемый скриптом, менюбар через `NSStatusItem`
- Перехват клавиатуры: fn — запись, fn+пробел — фиксация, Esc — отмена
- Запись микрофона со стартом и стопом вместо фиксированной длительности
- Распознавание локально через уже написанный `ParakeetTranscriber`
- Чистка текста через DeepSeek V4 Flash
- Вставка текста в чужое приложение через буфер обмена
- Плавающая панель: получатель, уровень звука, стадия обработки, отказ
- Звуковая обратная связь
- Второе системное разрешение — универсальный доступ

**Не входит**

- Окно настроек: конфиг правится в json
- Словарь замен и окно ручной правки слова — см. раздел 14
- Автозапуск при входе в систему
- Всё из фазы 2: ScreenCaptureKit, две дорожки, очередь, диаризация, markdown

## 2. Форма проекта

Остаёмся на чистом Swift Package. Приложение собирается скриптом, Xcode-проекта нет.

Причина: менюбар-приложение без окон не выигрывает от Xcode почти ничего, а `.pbxproj` плохо читается и плохо правится. Скрипт же лежит в гите текстом и одинаково запускается человеком и агентом. Это отменяет строчку в `ARCHITECTURE.md` про Xcode-проект, подключающий `Core` локальной зависимостью.

### Таргеты

```
Package.swift
├── Core          библиотека, есть    + Core/LLM/         клиент DeepSeek, промпты
│                                     + Core/Audio/       запись со стартом и стопом
├── Dictation     библиотека, новая     Features/Dictation/
│                                       автомат, перехват клавиатуры, вставка текста
├── App           исполняемый, новый    App/
│                                       NSApplication, статус-бар, панель
└── CLI           исполняемый, есть   + команда dictate
```

Зависимости строго в одну сторону:

```
App ──► Dictation ──► Core
CLI ──► Dictation ──► Core
```

`Dictation` не импортирует ничего оконного и не знает о существовании панели. `App` не знает, как устроена диктовка: он подписан на её состояние и рисует. Границу держит компилятор, а не договорённость.

Тестовые таргеты: `CoreTests` (есть), `DictationTests` (новый), `CLITests` (есть).

### Бандл

```
NoHands.app/
  Contents/
    Info.plist
    MacOS/NoHands
```

`Info.plist` лежит в репозитории как `App/Info.plist`:

| Ключ | Значение | Зачем |
|---|---|---|
| `CFBundleIdentifier` | `com.nohands.app` | к нему привязываются выданные разрешения, больше не меняется |
| `LSUIElement` | `true` | живём в менюбаре, в доке не появляемся |
| `NSMicrophoneUsageDescription` | текст | без него запрос микрофона падает |
| `LSMinimumSystemVersion` | `14.0` | как в `Package.swift` |

`Scripts/make-app.sh`: `swift build -c release --product NoHands`, раскладка каталогов, копирование `Info.plist`, подпись. Ни одного шага, который нельзя повторить из терминала.

### Подпись

Ad-hoc подпись записывает в требование к коду хеш самого бинарника. Пересборка его меняет, macOS видит другую программу, и разрешение «универсальный доступ» перестаёт действовать — причём галочка в системных настройках остаётся на месте, так что отказ выглядит как поломка перехвата клавиатуры.

Поэтому подписываем самоподписанным сертификатом `NoHands Local`. Требование становится «этот идентификатор, подписанный этим сертификатом», хеш в него не входит, разрешение переживает пересборки. Сертификат создан вручную в Связке ключей до начала работ.

Защищённая среда выполнения (hardened runtime) не включается: она потребовала бы entitlement на микрофон, ничего не дав взамен — приложение не распространяется и не нотаризуется.

### Ручные настройки

| Что | Когда | Как |
|---|---|---|
| Ключ DeepSeek в Keychain | до задачи 2 | `security add-generic-password -s nohands-deepseek -a api-key -w` |
| Действие клавиши fn → «ничего не делать» | до задачи 5 | Системные настройки → Клавиатура |
| Универсальный доступ для `NoHands.app` | перед задачей 5 | Конфиденциальность и безопасность |

Разрешение на микрофон запрашивается само при первой записи. Разрешение на запись экрана в фазе 1 не появляется — оно из фазы 2.

## 3. Конвейер

```
fn нажата
  → StreamingRecorder.start()          16 кГц моно WAV во временный файл
  → уровни наружу 20 раз в секунду     панель рисует
  → зафиксирован получатель            NSWorkspace.frontmostApplication
fn отпущена (или fn нажата в режиме фиксации)
  → stop() → URL
  → ParakeetTranscriber.transcribe     локально, доли секунды
  → DeepSeekClient.clean               облако, ~2,2 с
  → TextInserter.insert                буфер обмена + Cmd+V + возврат буфера
```

Промежуточных вставок нет: текст появляется один раз и сразу чистым. Вариант «сначала сырой, потом подмена» отвергнут — правка чужого поля задним числом ломается везде, где есть автодополнение или автоотправка.

Заявленная в `DESIGN.md` задержка около секунды при этом не достигается: фактически около 2,4 с. Цифра проверяется на реальном использовании, а не подгоняется заранее.

## 4. Конечный автомат

Ядро диктовки — чистый тип без единого системного вызова: на вход события, на выход список эффектов. Ни протоколов ради тестов, ни моков.

```
   idle ──fn──► recording(удержание) ──пробел──► recording(фиксация)
                    │        │                        │
       fn отпущена  │        │ fn отпущена            │ fn нажата
       раньше 0,3 с │        │ позже 0,3 с            │
                    ▼        ▼                        ▼
                 отмена    ────────► transcribing ◄────
                 молча                    │
                                          ▼
                                      cleaning ──отказ──┐
                                          │             │
                                          ▼             ▼
                                      inserting ◄── inserting(сырой)
```

**Состояния:** `idle`, `recording(режим, начало, получатель)`, `transcribing`, `cleaning`, `inserting`, `failed(причина)`.

**События:** нажата fn, отпущена fn, нажат пробел, нажат Esc, запись остановлена, распознано, вычищено, чистка отказала, вставлено, отказ, тик времени.

**Эффекты:** начать запись, остановить, выбросить запись, распознать, вычистить, вставить, показать панель в состоянии, скрыть панель, проиграть звук.

**Правила по краям:**

- Удержание короче 0,3 с — случайное касание fn. Отмена молча, без звука и без панели.
- Запись обрывается через пять минут. Наговоренное не теряется: обрабатывается как обычная диктовка. Защита от забытой фиксации.
- Esc отменяет всё до момента вставки, включая распознавание и чистку. Файл удаляется.
- В режиме фиксации остановку даёт нажатие fn; следующее за ним отпускание игнорируется.
- `failed` держится на панели три секунды и гаснет сам.

## 5. Перехват клавиатуры

`CGEventTap` в активном режиме на маске `flagsChanged | keyDown`, поднимается после проверки `AXIsProcessTrusted()`.

**fn — не модификатор.** Флаг `.function` (`kCGEventFlagMaskSecondaryFn`) выставляется стрелками, F-клавишами, Home и End. Ловить по флагу — значит начинать запись на каждой стрелке. Единственный надёжный признак — код клавиши 63 в событии `flagsChanged`.

Коды клавиш: fn — 63, пробел — 49, Esc — 53.

**Решение о проглатывании принимается синхронно.** Обработчик тапа обязан вернуть событие или `nil` немедленно, а автомат живёт в своей очереди. Поэтому монитор держит два атомарных флага, которые обновляются при смене состояния: «глотать пробел» (только во время удержания) и «глотать Esc» (пока идёт диктовка до вставки). Обработчик сравнивает код клавиши с тремя числами, смотрит флаг, кладёт событие в очередь и возвращает управление. Ничего тяжелее в нём не делается никогда.

**Тап глохнет.** Если обработчик задумался, macOS шлёт `.tapDisabledByTimeout` и выключает тап насовсем — молча. Отдельная ветка ловит это событие и включает тап обратно.

**Приватность.** Тап на `keyDown` видит каждое нажатие в системе. Приложение сравнивает код клавиши с тремя числами и больше ничего с событием не делает: не копит, не пишет на диск, не отправляет. Это расширение по сравнению с исходным замыслом, где предполагался только `flagsChanged`, — записано отдельным решением в журнал.

## 6. Вставка текста

Порядок, в котором каждый шаг существует по конкретной причине:

1. Сохранить прежнее содержимое буфера обмена и его `changeCount`.
2. Положить в буфер вычищенный текст, запомнить новый `changeCount`.
3. Если активное приложение больше не то, что зафиксировано в начале записи, — вернуть зафиксированное на передний план и дождаться фокуса, но не дольше 300 мс.
4. Послать `CGEvent` нажатия и отпускания V с флагом команды. **Флаги очищаются от всего остального**, иначе зажатый в этот момент Shift или Option уедет в событие.
5. Подождать. Приложение-получатель читает буфер асинхронно; возврат прежнего содержимого следующей строкой вставит старый текст.
6. Вернуть прежнее содержимое — **только если `changeCount` всё ещё наш**. Если за это время в буфер положили что-то ещё, чужое не затирается.

Шаг 3 существует потому, что попадание наговоренного в чужое окно — худший вид отказа: он тихий.

## 7. Панель

`NSPanel` со стилем `.nonactivatingPanel`, `canBecomeKey = false`, уровень `.floating`, снизу по центру над доком. Содержимое на SwiftUI.

`.nonactivatingPanel` и `canBecomeKey = false` обязательны: иначе панель сама станет активным окном и текст уйдёт в неё.

| Стадия | Что показано |
|---|---|
| запись | иконка и имя получателя, уровень звука, крестик отмены |
| фиксация | то же плюс признак, что запись идёт без удержания |
| распознавание, чистка, вставка | бегущая полоска с подписью стадии |
| отказ | красная строка с причиной, три секунды |

Уровень считается по среднеквадратичному значению каждого буфера, обновление 20 раз в секунду. Честного прогресса у конвейера нет — ни распознавание, ни один запрос к API его не дают, — поэтому полоска бегущая, а не заполняющаяся, и подписана стадией.

Панель появляется на старте записи и уходит через 0,6 с после вставки.

## 8. Чистка через DeepSeek

`Core/LLM/DeepSeekClient.swift`, промпт — в конфиге.

**Обязательно:** `thinking: {"type": "disabled"}` в каждом запросе. Без него модель уходит в рассуждения, не доходит до ответа и тратит в тридцать пять раз больше выходных токенов — сорок центов в месяц превращаются в четырнадцать долларов. `reasoning: {"enabled": false}` не работает, проверено в фазе 0.

Точный адрес, заголовки и форма тела фиксируются задачей 2 против живого API, а не по памяти. В тестах проверяются сборка запроса и разбор ответа, сеть не трогается.

Таймаут десять секунд.

Промпт по смыслу: убрать заполнители и самоисправления, расставить пунктуацию, сохранить регистр и содержание, ничего не добавлять и не пересказывать, вернуть только текст. Живёт в конфиге, чтобы правиться без пересборки.

Словаря терминов в фазе 1 нет. В фазе 0 он передавался в Scribe через keyterm prompting, но у Parakeet в FluidAudio 0.14.8 механизма подсказок нет, а класть словарь в промпт чистки — ровно тот вариант, который фаза 0 назвала худшим: восстанавливать испорченное слово хуже, чем подсказать его распознаванию. Несколько дней использования покажут, ломается ли что-нибудь вообще.

## 10. Отказы

Каждый отказ называется вслух. Молчаливой подстановки пустой строки нет нигде.

| Что случилось | Что делаем |
|---|---|
| нет устройства ввода | панель: ошибка, звук отказа |
| запись не поймала ни кадра | панель: скорее всего нет разрешения микрофона |
| запись слишком коротка для распознавания | панель: слишком коротко. Порог задаёт сам Parakeet |
| распознавание отказало или вернуло пусто | панель: причина. Текста нет, вставки нет |
| чистка отказала: нет сети, нет ключа, таймаут, пустой ответ | **вставляем сырой текст**, панель говорит «без чистки» и называет причину, звучит звук отказа |
| нет разрешения универсального доступа | панель: как его выдать. Текст остаётся в буфере обмена |

Отказ чистки — единственное место, где работа продолжается после ошибки. Это не молчаливый фолбэк: отказ назван и озвучен, просто наговоренное не выбрасывается из-за сетевого сбоя.

Тексты сообщений об ошибках — английские, как во всём коде проекта; панель показывает их как есть.

## 12. Порядок задач

Внутри фазы действует тот же принцип, по которому разделены сами фазы: одно новое системное умение за раз, чтобы при поломке было понятно, что именно отвалилось.

| | Что | Новое умение | Чем проверяется |
|---|---|---|---|
| 1 | Запись со стартом и стопом вместо фиксированной длительности, уровни наружу | — | тесты и команда `record` фазы 0 продолжают работать |
| 2 | `nohands dictate`: запись по Enter, Parakeet, DeepSeek, печать в терминал | облако | конвейер целиком без бандла и без разрешений |
| 3 | Бандл, `Info.plist`, скрипт сборки, подпись, статус-бар с меню | бандл | приложение живёт в менюбаре и выходит по пункту меню |
| 4 | Автомат диктовки | — | тесты на все переходы |
| 5 | Перехват fn, пробела, Esc; звуки | универсальный доступ | звуки в нужные моменты, wav на месте, стрелки и F-клавиши ничего не запускают |
| 6 | Вставка текста | — | проверка в трёх разных приложениях, включая одно с автодополнением |
| 7 | Панель | — | глазами |
| 8 | Задел под правку слов: последняя диктовка — wav, сырой текст, чистый текст — живёт в памяти до следующей | — | тестом на автомате |

Разрешение универсального доступа появляется на задаче 5 вместе с тапом, а не на задаче 6 вместе со вставкой: тап поднимается только после `AXIsProcessTrusted()`, значит без разрешения не работает уже он.

## 14. Открытые вопросы

**Как вести словарь испорченных слов.** Испорченное слово видите только вы и только в секунду, когда текст уже вставлен. Автоматически его не поймать: DeepSeek не исправит фамилию, которой не знает, значит расхождение «сырой → чистый» такие случаи не покажет. Пассивный сбор отпадает — логировать распознанный текст запрещено. Задел в фазе 1 — последняя диктовка целиком живёт в памяти; механизм пометки и хранилище словаря решаются после нескольких дней использования, когда станет видно, часто ли это вообще нужно.

**Реальная задержка.** 2,4 с — сумма замеров фазы 0 на коротких образцах. На длинных фразах она может оказаться другой. Измеряется в работе, не гадается заранее.

**Автозапуск при входе.** Одна строка через `SMAppService`, но добавляется тогда, когда приложением начнут пользоваться постоянно, а не раньше.
